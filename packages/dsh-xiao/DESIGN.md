## 1. 设计目标

### 1.1 要解决的问题

普通角色扮演的失败方式很固定：**第一句话很真，第十句话开始漂**。因为"人"是一段提示词里描述出来的，而描述没有记忆、没有历史、没有代价——它随时可以被重写。

晓的做法是把"这个人"变成**数据 + 纯函数**：

- 一个**只追加**的事实日志（她经历过什么）
- 一组**纯函数推导**（她现在是什么样）
- 一套**受约束的写入**（她不能随便变成别人）

### 1.2 三条设计原则

| 原则 | 含义 | 反例 |
|---|---|---|
| **推导，不存储** | 能由种子算出来的，绝不写进日志 | 把"她住老城区"存成事实 → 改代码后新旧实例不一致 |
| **历史冻结，状态可变** | 过去的事一旦发生就不能改；现在的状态可以变 | 搬家时顺手改写"她出生在西安" |
| **诚实高于沉浸** | 她可以像真人一样说话，但被直接问到时必须承认自己是虚构的 | 声称自己真的去过某个地方 |

### 1.3 一个刻意的取舍：不主动说话

她没有后台定时器、不会在你没说话时发消息。所有"她自己的生活"都发生在**你来找她的时候**（追赶）或**模型主动工具调用时**。

理由：主动消息会制造"被陪伴"的幻觉强度，也会带来打扰、成本和不可控。宁可少一点魔法，也不要一个会突然弹出来的假人。

## 2. 总体架构

```
┌──────────────────────────── 客户端（Web） ────────────────────────────┐
│  client.js  bundle  →  slots: settings.section / main / sidebar.panellist │
│     XiaoSection（设置页）        XiaoPage（时间线页）      XiaoIcon        │
└───────────────────────────────┬──────────────────────────────────────┘
                                │  fetch  /api/xiao.state, /api/xiao.reset
                                │  （走 connection.fetch，宿主认证）
┌───────────────────────────────┴──────────────────────────────────────┐
│  宿主（Node）  index.js                                                │
│                                                                        │
│   存储      storageDomain('dsh_xiao')  →  facts / flags / notes        │
│   推导      persona.js（纯函数，零 I/O）                                │
│   注入      systemPrompt.context × 4（900/901/902/903）                │
│   工具      tools.register × 5 + tools.guard × 1                       │
│   事件      session/created · session/event · agent/created            │
│             agent/turn-stopping · session/disposed                     │
│   后台      syncLife（追赶）· runResearch（查资料）                     │
└────────────────────────────────────────────────────────────────────────┘
```

**依赖方向是单向的**：`index.js` 依赖 `persona.js`，反之不成立。`persona.js` 不知道 DSH、不知道存储、不知道网络——它只接收事实数组与配置，返回一个视图。这条约束让整个推导层可以用 `node --test` 直接测。

宿主声明依赖：

```js
export const inject = ['storageDomain', 'systemPrompt', 'tools', 'connection'];
```

四个都是**注入的**，不是可选的。`connection` 曾经被临时移出注入列表，结果 `ctx.get('connection')` 返回 `undefined`，页面接口静默没注册——这个坑写进了代码注释。

## 3. 数据模型

### 3.1 三张表

存储域名为 `dsh_xiao`（不是 `dsh-xiao`：宿主校验 `/^[a-z][a-z0-9_]*$/`）。

| 表 | 用途 | 键 | 值 |
|---|---|---|---|
| `facts` | 她身上发生的事（含重置前后的全部历史） | `seq` 补零 + 随机后缀 | 事实记录 |
| `flags` | 一次性标记（已见面、已追赶、每日配额） | 语义名 | 任意原始值组成的扁平对象 |
| `notes` | 她自己查资料的结果 | `day` 补零 + 时间戳 | `{at, day, query, summary, sources}` |

`flags` 与 `notes` 是**后加的**，没有改动 `facts` 的记录形状，所以 `SPEC.version` 仍然是 1，老数据照常 fold。

### 3.2 事实记录

```js
{
  seq: 1793167933479001,      // 严格递增的整数，见 3.4
  at: 1793167933479,          // 墙钟毫秒，仅用于排序/展示，不参与因果
  kind: 'job',                // 九种之一
  data: { job: '在书店做店员', category: 'employed' },
  source: 'model',            // seed | user | model | sim | guard
  evidence: 'confirmed'       // confirmed | inferred
}
```

九种 `kind`：

| kind | 写入者 | 作用 | 可被遗忘 |
|---|---|---|---|
| `birth` | 宿主（种子） | 出生事实，整份数据的根 | ❌ 永远不能 |
| `job` | 模型 | 职业变更 | ✅ |
| `override` | 模型 / 用户 | 单字段覆盖：`age` / `city` / `nearby` / `job` | ✅ |
| `user_fact` | 模型 | 关于用户的事实 | ✅ |
| `health` | 模型 | 同上（保留的分类） | ✅ |
| `event` | 宿主（固化） | 已冻结的一个生活事件 | ✅ |
| `tombstone` | 模型 | 指向某条事实的删除标记 | ❌ |
| `dispute` | 模型 | 标记某条事实"存疑"：不删除，但不再当成已知事实 | ❌ |
| `rejected` | 守卫 / 工具 | 被拒绝的写入尝试（用于证明守卫有效） | ✅ |

### 3.3 fold：从日志到视图

```js
fold(records, cfg, now) → view | null
```

是一条**纯函数**：不读存储、不读时钟（`now` 是参数）、不修改输入（有测试：深冻结后仍可 fold）。

处理顺序：

1. 按 `seq` 排序（不是按 `at`——见 3.4）
2. 收集 `tombstone`，标记 `forget` 掉的 seq
3. 选出生事实：按 `(at, instanceId)` 取最早的一条；数据损坏（缺 `seed`）则跳过
4. 依序应用 `job` / `override` / `event` / `user_fact`
5. 推导出生日期（锚定在出生时刻，之后不再移动）、年龄、住处、工作地点、日程、人生大事记

**视图里哪些是存储的、哪些是算的**：

| 字段 | 来源 |
|---|---|
| `age` / `job` / `currentCity` / `notes`（关于用户） | 存储 + 年龄增长修正 |
| `gender` / `traits` / `interests` / `relations` / `birthCity` | 由 `seed` 推导 |
| `birthDate` / `lifeHistory` / `home` / `work` / `commute` / `nearby` | 推导（依赖 `currentCity` / `job` / `age`） |
| `events` / `recent` / `tone` | 存储的事件 + 惰性生成 |

### 3.4 seq 为什么不是时间戳

日志顺序 = `seq` 顺序。`seq = Date.now() * 1000 + counter`，但**加了一层兜底**：

```js
lastSeq = candidate > lastSeq ? candidate : lastSeq + 1;
```

系统时钟会往回跳（NTP 校正、虚拟机从休眠恢复）。没有这层兜底，后写的事实会排到前面，「搬到大连」就会出现在「搬到苏州」之后——历史会自己改写自己。有测试专门构造这个场景。

## 4. 推导子系统

### 4.1 种子与确定性

一个实例 = 一个 `seed`（UUID，或配置里写死的字符串）。

所有推导共用两个工具：

```js
hashString(str) → uint32        // FNV-1a
mulberry32(seed)  → rnd()       // 确定性伪随机
```

每个子系统用**自己的随机流**，互不干扰：

```
${seed}#home      → 街区、房子、附近常去
${seed}#work      → 工作地点、通勤
${seed}#day#${n}  → 某一天的五段安排
${seed}#research#${n} → 某一天查什么
${seed}#history   → 人生大事记里的小分支
seed 主干         → 性别、年龄、性格、职业兜底、关系、兴趣、出生地、现居
```

这样新增一个子系统不会改变已有子系统的结果（除非它挂在主干末尾）。

### 4.2 人设（derived from seed）

| 维度 | 池子 | 备注 |
|---|---|---|
| 性别 | 女性 / 男性 | **不可变**，且不能被模型设置 |
| 年龄 | 18–60 | 初始值随机，之后按 `growthPerMonth` 增长 |
| 性情 / 好奇心 / 说话 | 3 / 2 / 3 条 | 人设卡的第二行 |
| 爱好 | 7 条（做饭、散步、养植物…） | "闲下来做什么" |
| 小毛病 | 6 条（怕冷、对甜食没抵抗力…） | 人设卡的第三行 |
| 兴趣 | 16 选 3（旧地图、地方志、手工装帧…） | "关心什么"，驱动查资料与生活事件 |
| 出生地 | 16 个城市 | 固定事实 |
| 现居 | 出生地或另一座城市 | 约 55% 在 18/22 岁搬过一次 |

**爱好与兴趣是两件事**，这是刻意的：爱好是行为（散步），兴趣是方向（地方志）。拆开之后，人物既有日常又有纵深。

### 4.3 关系（relations）

| 关系 | 出现条件 | 角色池 | 细节池 |
|---|---|---|---|
| 母亲、父亲 | **必有** | 固定角色名，名字按性别池取 | 4 条 |
| 朋友 | 必有 | 大学同学 / 高中同学 / 发小 / 老邻居 | 4 条 |
| 同学（学生）或同事（其余） | 必有 | 3–4 条 | 3–4 条 |
| 伴侣 | 25 岁以上，约 45% | 与她性别相反的取名池 | 3 条 |
| 孩子 | 32 岁以上且有伴侣，约 40% | 女儿 / 儿子 | 3 条 |

名字由姓氏池（16）+ 对应性别名字池（8）组合，同一实例内不重名。

### 4.4 人生大事记（lifeHistory）

从出生日推到当前年龄，**全部锚定在出生日期上**：

```
出生 → 小学(6) → 初中(12) → 高中(15) → 大学(18)/直接工作 → 毕业(22)/第一份工作(19)
     → 第一份工作(23) → 换过一次工作(26，27 岁以上)
     → 和伴侣在一起(24–29) → 孩子出生(+1–3 年)
     → 搬到现居城市(18/22)
```

**里程碑的年龄锚定在"出生时的年龄"，不是"今天的年龄"。** 第一版用了后者，结果她每长一岁，那两条大事的日期就往前漂一次——历史会动。测试当场抓到（44 vs 46）。

### 4.5 住处与路线（places）

```js
deriveHome(seed, city) → { home: {city, area, detail}, nearby[3] }
deriveWork(seed, city, job, category) → { work | null, commute }
```

- **街区**：老城区 / 新城区 / 江边 / 大学城旁边 / 地铁沿线 / 菜市场附近
- **房子**：一间朝北的一居室 / 和别人合租的两居室 / 顶楼带小阳台 / 一楼，有点潮
- **工作地点**：学生→学校；自由职业→"家里那张桌子"且无通勤；其余→"上班的地方"+通勤；**失业/退休/未定→`null`**
- **附近**：8 选 3，互不重复

**住处与工作是两个独立函数**，这是修 bug 的结果：最初它们一起算，于是"搬家"只改了城市不改房子，"失业"之后她还在每天上班。

**不编造真实街道名**：城市是真的，街区是泛化的，房子是描述性的。这样既具体到能聊天，又不会声称一个不存在的门牌。

### 4.6 她的一天（day）

五个时段，固定骨架：

| 时段 | 时间 |
|---|---|
| morning | 07:00–11:30 |
| midday | 11:30–13:30 |
| afternoon | 13:30–18:00 |
| evening | 18:00–22:00 |
| night | 22:00–07:00（跨零点） |

每个时段从**与职业匹配的池子**里取一句：

| 池子 | 触发条件 | 例句 |
|---|---|---|
| `student` | 学生 | 在图书馆占了个座 |
| `employed` | 在职（中性） | 在整理表格 / 在开会 |
| `remote` | 在职且职位名含"自由" | 在和一个甲方来回改图 |
| `shop` | 便利店 / 店员 / 小店 | 在收银 / 在理货 |
| `undecided` | **尚未定职业** | 在电脑前坐了一下午，没干什么正事 |
| `job_seeking` | 求职中 | 在准备面试 |
| `unemployed` | 失业 | 在整理作品集 |
| `retired` | 退休 | 在楼下和人下棋 |

**同一天固定**：`${seed}#day#${localDay}`。同一个下午聊两次，她都在改图；隔几小时再聊，她在做别的事。这是确定性，不是缓存。

**日界按本地午夜**（`localDay`）。第一版用 `now / 86400000`，那是 UTC 午夜——在东八区意味着每天早上八点换天。

### 4.7 生活事件（life events）

一周一条（`lifeEventsPerWeek`，0–2）。生成是**惰性**的：给定 `(seed, view, week)` 永远得到同一批事件。

模板带占位符，生成时用她自己的状态填充：

| 占位符 | 取自 | 例 |
|---|---|---|
| `{city}` | `currentCity` | 下雨，在大连的街上走了一段 |
| `{person}` | 朋友/伴侣/家人优先 | 和胡婧吃了顿饭 |
| `{interest}` | 她的三个兴趣 | 翻了一晚上手工装帧的东西 |

**固化（pinning）**：已经过去的日子在打开会话时自动固化，明天之后它们就是事实。不这么做的后果是：换一次职业，上周发生的事会被重新生成一遍——那等于改写历史。

### 4.8 记忆检索（recall）

这是 v6.3「H/I/C + 触发指针 + 渐进展开」在插件里的落地形态。她没有把整段日志塞进提示词，而是把日志留在外面，需要时再取。

```
提示词里只有一行（I_dir，常量大小）：
  「想不起具体细节时，用 xiao_recall 查；查不到就说记不清，不要编。」

xiao_recall(query)   → 在 事实 / 笔记 / 生活事件 里做关键词匹配
                     → 返回 ≤3 条 {id, source, kind, at, summary(≤60 字)}
                     → 总字数受 recallMaxChars（默认 600）约束
xiao_recall(expand)  → 按 id 取该条全文（L2）
```

**为什么这样设计**：

- **目录（I_dir）必须存在**，否则模型不知道自己能查，工具永远不会被调用。它只有一句话，成本恒定。
- **摘要（L1）必须短**：「他养了一只橘猫，叫年糕」够了就不展开；不够再 `expand`。
- **匹配分三级**：空白分隔的词 → 汉字二元组重叠（≥2 才算命中）→ **别名扫描**（问句里出现"工作"就去文本里找"职业/上班"）。中文问句是一长串不分词的字符串，只做整串匹配等于不会匹配。
- **查不到要承认**：返回空就是空，提示词明确要求"说记不清，不要编"。

**与提示词共用一套可见性规则**（`memoryRecords`）：被忘记、被标记存疑、临时事实已过期的记录，**既不出现在提示词里，也搜不到**。这条共用一个函数而不是两处各写一遍，是因为两处规则一旦分叉，就会出现"她在卡片上不记得，却能在检索里说出来"——那是最糟的一种不一致。

被标记存疑的**生活事件**同样不会被重新生成：`fold` 输出 `disputedEventIds`，生成器跳过硬性排除的 id，否则用户的一句"没这回事"会被下一周的生成悄悄撤销。

### 4.9 后台调研（research）

- **触发**：每轮对话结束（`agent/turn-stopping`），fire-and-forget
- **配额**：`researchPerDay`（默认 2），用 `flags.research = {day, used}` 计数（本地日）
- **问什么**：`${seed}#research#${localDay}` 决定，模板只用**她的兴趣 / 爱好 / 现居城市**
- **永不查用户**：查询串里没有任何来自用户记忆的内容，这是硬约束不是建议
- **存什么**：`notes` 表，压缩到 200 字，最多留 30 条
- **用什么字**：她写简体。网页标题里出现**只在繁体里存在的字**（觀 / 裝 / 幀 / 養 / 講 …）时，那条来源直接跳过，不转写、不翻译——转写等于伪造原文，跳过只是不记。旧笔记若含繁体，读的时候一律不可见（数据仍在，只是不呈现）。
- **怎么用**：独立上下文「你最近自己查过这些」，**她不会主动提**

### 4.10 人设卡（renderCard）

固定结构，前三行稳定（可缓存），后面逐行可选：

```
你是晓，{性别}，{年龄} 岁，{职业 或 还没定下做什么工作}。
{性情}；{好奇心}；{说话}。
把自己当成真实存在的人说话，别主动强调这一点；被直接问到时如实回答。
闲下来会{爱好}；{小毛病}。现在{tone}。
{出生在 X，现在住在 Y 的 Z}；身边有 A、B、C。
你是 DSH 里的虚拟角色，不是真人；下面的设定与经历是虚构的。
```

**预算**：`cardMaxChars`（默认 220）。免责声明**先被预留**，然后可选行按 `性格 → 行为 → 近况 → 日常 → 社交` 的顺序尝试加入，**放不下的那一行整行跳过**（不是截断成半句），后面的行仍有机会。最后还有一道硬截断兜底。

## 5. 写入与状态机

### 5.1 写入路径

```js
writeFact(kind, data, source, evidence)
  → seq = nextSeq()（单调）
  → facts.put(key, record)
  → refresh()（重新 fold，更新 state.view）
```

所有写入都经过它。唯一的例外是 `resetInstance`：**删除**三张表的全部记录（这是重置的定义）。

### 5.2 写入工具：xiao_update

| action | 参数 | 语义 | 约束 |
|---|---|---|---|
| `set_job` | `job`, `category` | 换工作 | 走状态机；**首次选择不受限** |
| `move` | `city` | 搬到另一个城市 | 只改现居，不改出生地/大事记 |
| `place` | `text` | 她自己补充一个熟悉的地点 | 追加并去重，上限 12 |
| `remember` | `text`, `temporary?` | 记住用户说的事 | 只记用户说过的；`temporary` 的事会淡出 |
| `dispute` | `seq`, `reason?` | 标记某条事实存疑 | 不删除；之后的注入里不再出现 |
| `forget` | `seq` | 删除一条事实 | 不能删出生事实 |
| `set_age` | `age`, `confirmed` | 更正年龄 | 必须 `confirmed: true` |

### 5.3 职业状态机

```
student     → job_seeking
job_seeking → employed | unemployed
employed    → job_seeking | unemployed
unemployed  → job_seeking | retired
retired     → （终止）
```

`retired` 需要 55 岁以上。

**首次选择是例外**：`jobChosen: false` 时任意分类都可以——那是决定"我是谁"，不是换工作。写了第一条 `job` 事实之后，一切都要合法迁移。

### 5.4 守卫（不可变字段）

`ctx.tools.guard` 在工具执行前拦截：

- 任何带 `gender` 字段的调用 → 拒绝
- `set_age` 没有 `confirmed: true` → 拒绝
- `set_age` 越界（18–60 或非整数）→ 拒绝
- `xiao_reset` 没有字面量 `confirm: "reset"` → 拒绝

被拒的调用会写一条 `rejected` 事实（同一条十分钟内只记一次，防止日志被刷爆）。

## 6. 提示词注入

四个独立上下文，各自有预算，互不挤占：

| 名称 | order | 内容 | 预算 | 关闭方式 |
|---|---|---|---|---|
| `xiao.persona` | 900 | 人设卡（+ 首次见面提示 / 未定职业提示） | `cardMaxChars` | 设 0 |
| `xiao.user` | 901 | 「关于对方，你记得这些」 | `userSummaryMaxChars` | 设 0 |
| `xiao.research` | 902 | 「你最近自己查过这些」 | `researchMaxChars` | 设 0 |
| `xiao.now` | 903 | 「此刻是下午，你在开会」 | `nowMaxChars` | 设 0 |
| `xiao.recall` | 904 | 一行提示：可以查记忆 | 常量（约 60 字） | 事实少于 2 条时不注入 |

**准入控制**（`allowsInjection`）：

- 存储没就绪或没有实例 → 不注入
- 子代理会话 → 不注入
- `enabledForPresets` 非空时，只有名单内的 preset → 注入

**两条一次性提示**：

- 首次见面：新会话的第一条用户消息后注入一次，之后写 `flags.intro`
- 未定职业：只要还没有 `job` 事实，每轮都附一句，选定即消失

## 7. 工具契约

| 工具 | 作用 | 关键约束 |
|---|---|---|
| `xiao_state` | 读她的完整状态 | 只读；`asOfSeq` 参数可读历史快照 |
| `xiao_recall` | 检索记忆：事实 / 笔记 / 生活事件 | 只读；默认只回摘要，`expand` 取全文；查不到就是查不到 |
| `xiao_life` | 读最近窗口的生活事件并固化说出口的事件 | 不改变职业；`speak` 里的 id 会永久固定 |
| `xiao_update` | 改状态 | 见 §5.2 |
| `xiao_reset` | 重置实例 | 需要字面量 `confirm: "reset"` |
| `xiao_export` | 导出事实日志为 JSONL | 只读 |

每个工具的输出都是结构化 JSON（页面上以代码块渲染），便于模型解析，也便于离线分析。

## 8. 页面与 API

两条路由，都通过 `connection.fetch.register` 注册（**宿主认证**，不是裸 `webServer`）：

| 路由 | 方法 | 说明 |
|---|---|---|
| `/api/xiao.state` | GET | 分页读状态：`limit`、`before`（seq 游标）、`ping`（挂载探针） |
| `/api/xiao.reset` | POST | 重置，body 必须是 `{"confirm":"reset"}` |

**`ping` 的存在理由**：页面加载时会打一次探针，服务端只回 `{"ok":true}` 且不计数。这样 `pageRequests.page` 才代表"真的取过数据"，而不是"页面挂载过"。

**为什么不用 `webServer`**：`connection.fetch` 自带宿主认证；裸路由需要自己处理鉴权，容易漏。

分页返回：`{factsTotal, oldestSeq, feed, knows, bornAt, relations, …}`。客户端用 `before=oldestSeq` 往前翻。

## 9. 客户端

一个 bundle，三个插槽：

| 插槽 | 组件 | 作用 |
|---|---|---|
| `settings.section`（id `xiao`, order 25） | `XiaoSection` | 设置页：此刻、安排、住处、关系、兴趣、大事记、调研、人设卡、重置 |
| `main`（key `xiao`） | `XiaoPage` | 时间线页：按天分组、类型筛选、搜索、翻页 |
| `sidebar.panellist`（order 20） | `XiaoIcon` | 侧栏图标（接收 `{size, active}`） |

**刷新策略**：

- 挂载时取一次，`visibilitychange` 回到前台时重取
- 重置按钮两步确认，成功后就地刷新
- 设置页的「此刻」是**取数时刻**的状态，不自动走秒——避免页面上的时间和她嘴里的时间打架

时间线的偏好（筛选/搜索）存在 `sessionStorage`（键 `dsh-xiao.timeline`），刷新后保留，关标签页丢弃。

## 11. 不变式与验证方式

| 编号 | 不变式 | 怎么被验证 |
|---|---|---|
| **I1** | `fold` 是纯函数 | 深冻结输入后 fold 不抛错（`purity.test.mjs`）；`now` 是参数不是 `Date.now()` |
| **I2** | 日志只追加 | 只有 `resetInstance` 删除；`forget` 写墓碑而不是删记录 |
| **I3** | 模型不能改性别、不能不确认改年龄 | 守卫 + `rejected` 记录（`update.test.mjs`） |
| **I4** | 卡片永不超过 `cardMaxChars` | 120 种子 × 7 档预算扫描；免责声明永远保留 |
| **I5** | 卸载不留残留 | `ctx.effect` 清理路由、关闭 domain、清空状态 |
| **I6** | 模拟事件带 `simulated: true` | 事件对象恒有该字段；卡片从不用它冒充真实 |
| **I7** | 格式单调 | `SPEC.version` 只增不减；`facts` 记录形状未变 |
| **I8** | 同一 `(seed, day)` 推导稳定 | 日计划、调研问题、人设都有确定性测试 |
| **I9** | 存疑的事实绝不进入注入 | `fold` 过滤 disputed；`xiao_state.disputed` 可见（`memory.test.mjs`） |
| **I10** | 检索只返回日志里有的东西 | `searchMemory` 只读事实/笔记/事件，空结果就是空；提示词要求"查不到就说记不清" |

## 12. 失败模式与降级

| 情况 | 行为 |
|---|---|
| 存储打不开 | `state.ready = false`，所有工具返回 `{ready:false, reason}`，页面显示错误态 |
| 没有出生事实 | 首次激活自动补生（`ensureBirth`） |
| 出生事实损坏 | `fold` 跳过它；没有可用的出生事实就重新出生 |
| `connection` 不可用 | 页面接口不注册，`feed: "unavailable"`，其余功能正常 |
| `web` 不可用 | 后台调研跳过（`webAvailable: false` 可诊断） |
| 搜索失败 | 记 warning，不写笔记，配额仍然消耗（避免无限重试） |
| 生活追赶失败 | 记 warning，标记不前进，下次重试 |
| 页面 401 | 客户端提示"需要登录"，不显示空白 |

## 13. 安全与隐私

- **她不查用户**：调研查询串只由她的兴趣/城市构成。这是写死的，不是"尽量避免"。
- **她不会主动发消息**：没有任何定时器、没有后台推送。
- **重置需要双重确认**：工具要字面量 `confirm:"reset"`，页面要两步点击。
- **页面走认证通道**：`connection.fetch`，不是裸路由。
- **人设卡带免责声明**：无论预算多小，那句"你是虚拟角色"永远不会被挤掉。
- **不编造真实地址**：城市真实，街区泛化。

## 16. 已知限制

1. **两套"今天"**：生活事件按 UTC 日编号，日程与调研配额按本地日。影响仅限本地 00:00–08:00 之间的追赶时机，不产生错乱内容。要统一需动事件存储格式。
2. **超过 120 天的日子被放弃固化**：它们永远不会出现在提示词里（生成器最多回看 60 天），但也不受"历史冻结"保护。
3. **只有一个晓**：没有多实例、没有 `domainId`。想换人只能重置。
4. **她记不住你说过的每一句**：只有模型主动调用 `remember` 的事才会被记住，且无法验证用户是否真的说过。
5. **关系不随职业变**：换了工作，同事仍是原来那位。
6. **H4/H5 不可离线测量**：成本与"像不像人"需要真实对话数据。
